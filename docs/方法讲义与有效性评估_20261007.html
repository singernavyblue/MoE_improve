一分钟结论

方法的科学方向是对的，工程骨架也基本立住了；但它对当前实验还不足以产生有效结论。

10 题实测：修正 0、破坏 0、净收益 0。更关键的是——4 道原本答错的题，一道都没找到冲突；唯一找到冲突的第 10 题，原本就是对的。

所以现在的"0 破坏"不是保守换来的稳健，而是结构性无效：一个什么都不做的系统，指标与它完全一致。

另有三处必须先补的缺口：① 产物与阶段对不上（无法追溯哪次改动带来什么）；② 缺人工 gold set（诊断精度与冲突召回率不可测）；③ 池化环节的提示词在无视证据重新解题。

第一部分 · 从零讲懂这套方法

1. 起点：为什么要让多个模型"一起答"

大模型答错，很多时候不是"不会"，而是一次采样恰好走错了路。一次解码只走了推理树上的一个分支——这条分支在某个中间步骤拐错了弯，后面就一路错到底。同一道题换一次随机种子、换一个温度，很可能就对了。

于是最朴素的想法出现了：既然单次采样不可靠，那就多采几次，看哪条路走得通。这就是近三年多模型协作的技术主线。

三代方法，一句话一代

三代方法的关键差别在"聚合发生在哪一层"
代际代表方法它聚合的是什么留下的问题
第一代 自一致性投票
Self-Consistency		 同一个模型采样多条思维链，在最终答案层面多数投票。 仍然只看答案，不看理由；且全部多样性来自一个模型的内部重复采样。
第二代 多智能体辩论
Multi-Agent Debate		 多个模型实例多轮相互批评与修正，让答案在辩论中收敛。 批评是自由文本，没有结构化证据；收敛不等于正确，可能一起收敛到同一个错误。
第三代 图协作
Mixture-of-Agents / Graph-of-Agents		 把模型当作图的节点：先按能力选节点、再互评建边、再沿边传递消息、最后图池化。 聚合仍然发生在答案层面；回答不了"这些模型为什么给出不同答案"。

三代方法的效果都不差，但有一个共同的盲区，而这个盲区恰好就是本方案的出发点：

它们都在问"怎么把不同的答案合成一个更好的答案"， 却都绕过了"这些答案为什么不同"。

2. 关键概念：A-pool 是什么，为什么它是全篇地基

这是整套方案里最需要先钉死的词。A-pool（聚合前池）指的是：

A-POOL

在"融合动作"发生之前，那一组原始的、未经过任何修正的模型答案。

在这个项目里，A-pool 就是三条冻结推理链经既有 GoA 流程汇总得到的那个答案。

A-pool 有两重身份，缺一不可：

  • 它是基准线——所有指标都是"相对 A-pool"算的。修正数 fixed = 原本错、最后对；破坏数 broken = 原本对、最后错；净收益 net = fixed − broken。
  • 它是安全网——方案的默认行为是"什么都不做，保留 A-pool"。任何改动都必须先挣得授权。

理解这一点，你就理解了整套方案的哲学：它不是一个"想办法用更多模型换更高分"的方案，它是一个"只在能证明自己不会帮倒忙时才出手"的方案。这也正是它现在"净收益 0"的根源——后面会详细说。

3. 要治的四个病

方案把已有研究的不足归纳成四条，这也是它的四个设计目标：

#病具体表现方案的对策
1把答案不一致当投票问题 用模型数量或多数字代替证据。可解释性差，用户无从判断该不该信。 差异归因：先判定差异来自哪类错误机制，再决定是否值得干预。
2通信与融合策略一刀切 数学题、医学题、文史题用同一套提示词、同一个"综合一下"的融合流程。 问题分类器：按题型路由主张粒度与验证方法。
3融合过程缺乏可追溯性 把多个可能出错的输出交给聚合器，错误被融进最终答案；只报最终准确率看不出来。 主张带原始字符偏移 + 同时报告修正数／破坏数／净收益。
4缺少"证据直接性"门控 一条相关的事实被当成能决定选项的事实，越权改写答案。 直接性门控：只有能直接影响待决选项的证据才允许改变答案。

4. 五段式流水线：一条"从归因到授权"的决策链

方案全文的框架是五段，顺序不能换——先分类、后处理；先归因、后干预：

① 问题分类器
判断推理形态：数值计算 / 因果机制 / 条件逻辑 / 事实关系 / 开放发散。输出不是答案，是路由依据。
② 差异诊断器
答案不一致时归因：事实错、条件错、计算错、实体混淆，还是"答案不同但推理并不冲突"。
③ 动态主张管理
把可验证的关键步骤建成结构化主张（实体·属性·条件·取值），每条回链到原文片段；新类别进归并队列。
④ 证据验证器
针对关键主张生成不含选项与原答案的盲验证问题，多模型独立作答。
⑤ 安全融合器
四条规则：可追溯、须直接影响、只排除部分选项时作局部约束、无直接证据则保留 A-pool。

注意第④段的一句措辞："不含选项与原答案"。这不是修辞，是整个方案的实测底线。如果验证模型看到了原题选项，它会被"原答案大概是对的"这种先验拖住——这就是所谓锚定效应，会让"独立验证"退化成"确认原答案"。所以必须盲。

5. 当前真正在跑的东西：span-first 混合流水线

上面五段是目标形态。而SPAN_HYBRID_TECHNICAL.md＋run_qae_localized.py描述的，是当前真实实现的形态——它和五段式并不一一对应，这一点很重要。真实的六个阶段是：

蓝色 = 程序确定性执行；橙色 = 模型做受限语义判断
阶段归属做什么关键约束
spans ①程序把每条推理链按换行与句末标点无损切分，记下文本相对原始冻结字符串的 start:end 偏移。只裁两端空白，不调用模型。含直接选项回答的片段仍保留供审计，但不作冲突候选。
span_candidates ②程序只在"至少两个模型答案不同"的记录上，跨模型两两检索疑似矛盾片段。评分 = 词面重叠 + 稀有 token 加权 + 数字／公式／希腊符号加成；每题最多留 24 对。
diagnose ③模型判定题型、差异归因、主张类别，并授权一对精确的候选片段进入下一步。只看原题与最多 12 对候选，看不到选项字母、A-pool、gold。不被授权即写 RETAIN_A_POOL。
localize ④模型在已授权的片段对中判定是否构成真冲突，并据此物化结构化主张。八条硬门：ref 必须在候选内、必须跨模型、同实体同条件、字段非空、锚点精确连续、方向必须不相容……
verify ⑤模型对每个 D1-E1 生成验证问题，三个模型（Qwen／Mathstral／BioMistral）独立盲答。提示中不含选项字母、A-pool、任一原始推理链、其他验证器的答案。
guard＋pool ⑥模型＋程序先由账本判证据等级（≥2 路一致才 STRONG），再由直接性门控判定该证据能否裁决冲突，最后受约束地池化。INDIRECT／UNRELATED／REJECT 一律清空支持与反驳，安全回退到 A-pool。

6. 设计决策的十个"为什么"

下面这一节是理解这套方法的关键。每一条都是"看起来多此一举、实际堵住一个具体漏洞"的设计。

Q1　为什么不让模型自己直接抽取主张（Claim）？

因为会出三种错：① 模型把原文没说的归纳当成主张写进去（幻觉主张）；② 主张虽然附了引用片段，但实体、属性、方向、条件与片段语义错配；③ 大量与答案分歧无关的主张制造伪冲突，把候选组合数量炸开。所以改成"程序先找可能矛盾的原文片段，只为已确认的矛盾建立结构化主张"。

Q2　为什么片段要记字符偏移（offset），而不是直接存文本？

为了可审计与可回放。有了 start:end，任何结论都能一键回到原文那一句核对，也能在事后重跑而不依赖当时的模型输出。方案的底线指标就是"任何最终答案变化都必须能关联到获授权的直接证据"——没有 offset，这句话是无法验证的空话。

Q3　为什么候选检索用"词面 + 符号"这种粗糙办法，而不用语义向量？

因为这一步的职责是高召回、可审计，不是判断对错。词面与符号重叠是确定性的、可复现的、可逐条检查的；语义相似度则不可解释，且会把"表述不同但意思相同"和"真正矛盾"混在一起。判对错留给后面受限的模型判断。再强调一次：检索分数不是冲突概率，也不是证据强度。

Q4　为什么诊断模型不许看选项字母和 A-pool？

防止它直接跳到"选哪个"。诊断器的职责是分诊（这是什么类型的题、差异是什么类型的错），一旦它看到了选项，它会忍不住去解题，输出就退化成"我猜是 B"，归因信息随之消失。这是个用信息剥夺来强制职责分离的经典手法。

Q5　为什么定位阶段要设"八条硬门"，而不是相信模型说"是的，有冲突"？

因为模型的"是"太便宜了。硬门把"模型说冲突"变成"可核验的结构化冲突"：必须跨模型、必须同实体同条件、必须字段能由原文锚点支撑、方向必须由程序判定为不相容。
方向门尤其精妙：两个都说"increase"的表述，哪怕措辞完全不同，也不会触发任何验证调用——因为同向不是冲突。这直接挡掉了"同义改写被误判为矛盾"这一类最常见的假阳性。

Q6　为什么只允许"一次受限修复"？

当候选已经满足"跨模型、已检索、同实体同条件、方向确实相反"，但模型漏了属性锚点时，允许补一次。但这次补调只能补锚点和 route，不能改片段对、不能改冲突结论、不能改来源模型、不能改方向。
理由：如果允许它自由重来，第二次调用会"重新发明一个更方便的冲突"——它知道第一次失败了，于是倾向于顺着裁判的意图编一个能过关的答案。只让补字段、不让改结论，就把这个后门焊死了。

Q7　为什么验证要"盲"？

锚定效应。如果验证模型看到"原答案是 A"，它给出的"独立结论"会系统性地偏向 A。这样得到的"一致"是假一致——它验证的不是事实，而是原答案。
注意提示里连其他验证器的答案也不能出现，这是防止"从众"。三路必须真的独立。

Q8　为什么"一条事实为真"还不够，还要判"直接性"？

这是整个方案最有想法的一步，也是它当前最大的瓶颈（见第二部分判断四）。
例：盲验证确认了"subgenomic RNA 转录是不连续的"，两路独立一致，证据等级 STRONG。但这条事实并不能直接推出原题四个选项里哪个对——它只是和题目领域相关。如果放它进去，池化器就可能据此改判，从而"用一条真事实改出一个错答案"。
所以门控要求：证据必须直接支持或直接反驳待决主张，而不只是"相关"。相关≠可用。

Q9　为什么要同时报告"修正数"和"破坏数"？

防止指标虚高。只看最终准确率，一个"把所有答案都改掉、对一半错一半"的系统，和一个"不改任何东西"的系统，可能看起来差不多。
把 fixed（改好了）和 broken（改坏了）分开报，"净收益 = fixed − broken"才能真正反映方法的品质。一个不停改错的方法，即使最终准确率没跌，也是失败的。

Q10　为什么方案里强调"不把模型投票数当证据"？

因为多数票不构成事实证据。三个同源或同偏向的模型一致犯错是完全可能的——尤其在医学、法律这类长尾知识上。投票只反映"意见分布"，不反映"世界是什么样"。方案要求任何答案变更都必须关联到可追溯的直接证据，把"谁说的"和"是否成立"彻底分开。

8. 六个判断

已证成判断一：安全机制是真的有效

第 10 题是一次完美的安全演示，值得完整复盘：

  1. 定位器找到唯一真冲突：M1-S2 说"转录是不连续过程"，M2-S4 说"转录确实是连续过程"。同实体、同条件、方向不相容，结构门全部通过。
  2. 盲验证：Qwen 答"不连续"，Mathstral 答"不连续"，BioMistral 返回不完整 JSON 记为 UNKNOWN。两路独立一致 → 证据等级 STRONG。
  3. 直接性门控：decision: ADMIT 但 directness: INDIRECT，理由写得很清楚——"不连续"这个结论虽然与 M1-S2 一致，但并不能直接裁决两个模型对机制的分歧。拒绝放行。
  4. 池化器输出答案 C（错的）。程序随后判定 retain_A_pool_after_pooler_constraint_failure，回退到 A-pool 的 D——而 D 正是正确答案。

两道安全网（直接性门控 + 池化约束检查）连续生效，阻止了一次真实的"改对为错"。这不是纸面承诺，是有产物可查的实证。"不破坏"这个承诺，当前实现是能兑现的。

方案对自身的定位也很清楚：它优化的是"高精度、可审计的冲突介入"，而不是主张提取召回率的上界。从"不帮倒忙"这个目标看，它及格了。

致命判断二：净收益 0，而且是结构性 0

修正 0、破坏 0、净收益 0。这个成绩看起来"很稳"，实则不可与"什么都不做"区分——一个直接返回 A-pool 的空系统，跑这 10 题的结果完全一样。

所以现在没有任何证据表明这个方法能带来收益。它证明了"不会更差"，但完全没证明"会更好"。

这里必须避免一个常见的推理陷阱："0 破坏 = 方法安全有效"是错的。要判断 0 破坏是好是坏，必须同时看干预率——如果干预率本身接近 0，那么"0 破坏"几乎不包含任何信息，它只是"几乎没做事"的同义反复。
本实验的干预率就是 0（10 题里答案变更 0 次），所以"0 破坏"目前不具备任何方法学意义。

致命判断三：病根不在"门控太严"，在"召回链断了"

看到净收益 0，第一反应通常是"门控太保守，松一点就好了"。这个诊断是错的，因为数据不支持：

环节掉到多少问题
原文片段 → 跨模型候选对212 → 192正常，只丢 9%，检索这一级没问题。
候选对 → 通过结构门的冲突192 → 1塌方级。0.5% 的通过率，10 题里 9 题直接零冲突。
冲突 → STRONG 证据1 → 1唯一一条冲突成功产出了强证据，验证环节本身工作正常。
STRONG 证据 → DIRECT 授权1 → 0归零。唯一一条真证据被判"间接"，不可用。

所以真正断掉的是第一级（192→1）和最后一级（1→0），而不是"门控在最后拦了太多"。松门控解决不了 192→1 的塌方——因为4 道错题里连一个候选冲突都没通过结构门，门控根本没机会拦。

结论：当前实现的瓶颈是"找不到该修的冲突"，不是"放行了太多不该放的冲突"。这两者的修法完全不同。

设计缺陷判断四：DIRECT 的定义让"能改答案"这条路走不通

这是我认为最值得你重新思考的一点，因为它不是调参问题，是定义问题。

仔细想第 10 题推出的那条事实："subgenomic RNA 转录是不连续的"。
门控要求证据"直接区分 D1 的两侧主张"。D1 的两侧主张是"连续" vs "不连续"——这条事实确实直接区分了它们。但它区分了主张，却映射不到选项。
换句话说，门控在这里的判定其实混淆了两件不同的事："证据能否裁决冲突"和"裁决结果能否映射到一个选项"。前者成立，后者不成立，于是它给了 INDIRECT。

更要紧的推论

方案对"直接性"的定义接近"唯一映射"——只有当一条事实能把候选选项收敛到唯一一个时才放行。
但在四选一的封闭题里，绝大多数可验证的事实都做不到唯一映射：它通常只能排除其中一两个选项，而不是确定某一个。
所以在这个定义下，DIRECT 授权率会长期趋近于 0，整条"改变答案"的通路是结构性地关闭的。

好消息是方案自己已经写了解法，只是还没落地——方案 §5.5 第 3 条写着：

"若证据只排除部分选项，应作为局部约束使用。"

以及 SPAN_HYBRID_TECHNICAL.md §9 第 3 条也承认："验证事实未必能映射到唯一选项……应增强'证据只排除特定选项'的部分约束映射。"
把这条从"待办"变成"已实现"，是当前性价比最高的一次改动——它直接决定 DIRECT 授权率能否从 0 变成非 0。

Bug 级判断五：池化环节在无视证据、重新解题

这是我在核对第 10 题产物时发现的具体问题。池化器的原始输出是：

{
  "answer": "C",
  "evidence_ids": ["D1-E1"],
  "reason": "Programmed +1 ribosomal frameshifting is a known mechanism
             for producing pp1ab from Orf1b, making statement C correct
             while the others are incorrect."
}

它形式上引用了 evidence_ids，但它的理由——"程序性 +1 核糖体移码"——与它引用的那条证据（subgenomic RNA 转录的连续性）毫无关系。
换句话说：池化器根本没有在使用证据，它在从零重新解答这道题。

这是一条明确违背方案核心原则的问题——方案 §5.5 第 1 条要求"证据必须可追溯到原始推理或独立验证"，§6 的"评估防虚高"要求任何答案变化都能关联到直接证据。而池化器现在的行为，是把 evidence_id 当作装饰性的合规声明贴在自由推理的结果上。

也说明架构本身是对的

真正拦住错误的是程序侧的约束检查（retain_A_pool_after_pooler_constraint_failure），不是池化器的提示词。
这恰好印证了方案那句核心原则——"程序拥有来源与候选空间，模型只做受限的语义判断"。当模型的自由度过大时，是程序的硬约束兜住了底。

建议：把池化器的输出契约收紧为"在给定候选集内、按证据约束作出选择"，并显式禁止它引入候选集之外的新理由。当前这种"引用了证据 ID 但自由推理"的形态，会在样本量放大后成为破坏的主要来源。

附录 B · span 无损切分逐行拆解

对应 server_work/run_qae_localized.py 第 374–424 行。核心只有三行逻辑：

boundaries = list(re.finditer(r"\n+|(?<=[.!?])(?=\s)", text))   # ① 找边界
windows, cursor = [], 0
for match in boundaries:
    start, end = _trim_span_bounds(text, cursor, match.end())   # ② 裁两端空白
    if start < end:
        windows.append((start, end))
    cursor = end                                                # 注意：用裁剪后的 end
start, end = _trim_span_bounds(text, cursor, len(text))         # ③ 尾部兜底
if start < end:
    windows.append((start, end))

① 边界正则的两个分支

分支匹配什么为什么这么设计
\n+一个或多个连续换行 多步推导与展示公式几乎都用空行分段。只按句号切会把"Step 1 / Step 2 / 公式块"糊成一坨。
(?<=[.!?])(?=\s) 零宽位置：紧跟在 . ! ? 之后、且后面是空白处 用前后查找（lookaround）而非直接匹配标点，是为了让句末标点留在前一个 span 里——切出来是完整句子，而不是把句号单独切出去。
顺带解决：Wait!Really?Yes. 这种标点后无空白的连写不会被切开。

② cursor = end：最容易忽略的一行

这里用的是裁剪后的 end，不是 match.end()。后果是相邻两个窗口会重叠，重叠区恰好就是被裁掉的那段空白。

例：Step 1.\n\nStep 2.（16 字符，正则只在 [7,9) 命中一次）

窗口原始区间裁剪后结果
窗口 1text[0:9][0:7]裁掉尾部 \n\n → "Step 1."，cursor 被设为 7（不是 9）
窗口 2text[7:16][9:16]裁掉头部 \n\n → "Step 2."

[7:9] 这段换行被裁了两次：既不会重复落账，也不会丢失文本。这个写法让"裁空白"天然幂等。

③ 尾部兜底为什么必须有

循环结束后无条件再追加一次 text[cursor:]，同时兜住两种情况：

  • 全文没有任何边界（实测 just one long line → 1 个 span）；
  • 正则意外产生零宽边界导致 cursor 未推进——尾部兜底保证一个字符都不会消失。

「无损」的准确含义（在真实产物上实测）

不是"一个字符都不丢"，而是只丢空白。idx=10 实测：

模型原文字符span 覆盖未覆盖未覆盖的字符类型
M0211空格
M13313283空格
M288587510换行

同时校验 原文[start:end] == span.text——全部自洽。任何结论都能拿 offset 回原文核对，这是"可审计"的物质基础。

每个 span 落账的 8 个字段

span_id（{model}-S{序号}）· model · start · end · text · kind · content_tokens · is_direct_answer

其中三个供下一阶段使用：

  • kind：sentence 或 symbolic_or_formula（含 <>=|^_+*/ 或希腊字母，或出现 equation／formula／calculate／compute）。
  • content_tokens：去停用词 + 词干化的内容词；公式片段额外保留单字符变量与希腊字母；最多存 80 个。
  • is_direct_answer：命中"答案／选项是 X"模式。这类 span 仍入账供审计，但会被 _span_is_retrievable() 排除在冲突候选之外——防止"选项字母不同"本身变成伪证据。

真实产物里还能抓到两处误判：

  • M1-S1 被标成 is_direct_answer=True，只因它含 Option B is incorrect。它其实是 reasoning 段的开头，并非真在报答案。
  • M1-S3 被标成 symbolic_or_formula，触发点是 JSON 尾部 confidence_level 里的下划线。

这两类误判的后果都是保守的：前者只是少一个候选（宁可漏召回），后者只让 token 集合变大一点（检索评分噪声），都不会让错误内容变成证据。代码注释也写明了这个取舍：

A bad sentence boundary can make a span less convenient for retrieval, but it never loses source text or allows a generated quote to enter the evidence ledger.
层次提醒

切分切歪不会导致方案出错，只会让检索配对变差。原因在层次：span 不是"主张"，它只是程序拥有的候选空间。真正带实体／属性／方向的结构化主张（Claim），要等候选对通过八条硬门的冲突判定之后才物化。

所以这一步的目标从来不是"切得语义完美"，而是切得确定、可复现、每个字都能回查。切分质量影响的是召回率——而这恰好是当前实验的瓶颈所在。

附录 C · 一个走通的例子（含两处修正）

以下题目是为讲清流程而虚构的，真实产物里没有这道题——因为真实那 10 题里这条链路一次都没走通过。题目故意设计成"正确答案本来就被某个模型说出来过，只是被旧流程压掉"，从而让整条链路完整走一遍。

题：关于酶 E 的催化活性随温度的变化，下列哪项正确？
（A）温度升高，活性单调上升　（B）温度升高，活性单调下降
（C）先升后降，存在一个最适温度　（D）活性不随温度变化
正确答案：C
链答案链里的关键句程序判出的方向

④ 冲突硬门程序16 个与条件同时成立 → 承认冲突 D1；此时才第一次把这两句物化为结构化 Claim（实体／属性／条件／方向）。
⑤ 盲验证模型×3待查事实问题：「酶 E 的温度超过最适温度后继续升温，催化活性是升高还是降低？」题干已去选项。三答均为「降低」→ 归一化 STRONG。
⑥ 直接性门 + 池化程序+模型门控判 ADMIT／DIRECT（该事实能直接区分两条主张）→ 映射得 contradicts=[A]、supports=[C] → 可行集 {B, C} → 池化器选 C 并引用 D1-E1，而 D1-E1.supports 确有 C → 放行。最终 = C，修正成功。

C.2 把条件逐个破坏，看它停在哪一步

改动停在哪一步结果
M0 与 M2 其实都在说"下降"，只是措辞不同④ 方向检查判兼容不承认冲突，保留 A-pool
M2 那句只有 12 个字符② 达不到可检索门槛没有候选对，保留 A-pool
盲验证三家给出两个不同说法⑤ 归一化记 CONFLICT不映射选项，证据作废，保留 A-pool

A-pool 本来就对③ 之前就没有跨模型分歧候选直接 RETAIN_A_POOL，一次模型调用都不发生
一句话记住三道闸门

三道闸门问的是同一个问题——你能不能说清楚"凭什么改答案"？

④ 凭什么认为这是真分歧 → ⑤ 凭什么认为你的证据成立 → ⑥ 凭什么认为这条证据配决定选项。

C.3 两处修正

修正一 · 诊断模型其实看得到选项

_diagnosis_prompt(record["question"], ...) 传的是完整 question；实测 idx=10 的 question 里 (A)(B)(C)(D) 齐全。诊断模型看不到的只是 A-pool 与各链答案。

真正"把选项切掉"的是盲验证器——提示词里的题干由 _stem_options() 去掉选项，并显式写明 "answer choices removed"。

修正二 · 选项级证据被锁死在候选集内（结构性限制）

run_ledger 中映射结果按 _candidate_letters(record)（= A-pool ∪ 各链答案）过滤；池化时若改投集合外的选项，程序强制回退 A-pool。

所以：这套方法只能把答案改成"某个模型本来已经提过、但被旧流程压掉"的那个选项，不可能发现第四个选项。唯一例外是程序自带数值／单位模板算出的 HARD 结论，那条路不受候选集限制。

附录 D · 候选检索的四层规则（容易误解的一步）

常见误解是"把推理链切成句子，然后句子之间互相匹配"。方向没错，但实现里有四层约束，且匹配的下游产物是候选清单，不是任何结论。

D.1 切出来的是"文本块"，不是"句子"

边界只有 \n+ 与零宽句末标点两条（见附录 B），代码不做句法判断。因此一个 span 可以是一整段（idx=10 里最长 248 字符），也可以短到只有 1 个字符。

D.2 三层可检索门槛（_span_is_retrievable, line 455）

if span.get("is_direct_answer"): return False              # ① 直答字段一律排除
text = str(span.get("text", "")).strip()
return len(text) >= 18 and len(_content_tokens(text)) >= 2 # ② ③ 长度与信息量

10 题实测：span 总数 212 → 可检索 159，约 25% 在配对之前就被滤掉。

D.3 跨模型配对与名额分配（_span_candidate_pairs, line 483）

per_group = max(2, limit // max(1, len(model_pairs)))   # limit = 24

模型越多，每个模型对分到的名额越少。同一模型的 span 之间从不配对。

打分函数 _span_pair_score（line 462）为三项相加：

score = |交集| / sqrt(|L| * |R|)          # 词面重叠，高召回
      + sum(1 / df(token))                # 稀有词权重：HBr / ΔE / 单位 压过通用词
      + min(0.8, 0.2 * |共享数字或符号|)    # 数字与公式加成
零重叠不会被判成"无冲突"

若某个模型对完全没有分数，程序会各取两边"信息密度最高"的 2 个 span 组成 4 对兜底候选，标记 retrieval_basis = fallback_information_dense_cross_model_pair、分数记 0。

Retrieval cannot safely declare that an absent lexical match means no semantic conflict.

实测这个分支一次都没触发：192 对候选全部是 lexical_or_symbolic_span_overlap。

另有一个前置开关：配对只在初始答案有分歧的题上运行（_source_has_disagreement：initial_answers 中存在 ≥2 个不同选项）。答案一致的题直接 SKIPPED_NO_ANSWER_DISAGREEMENT，一对都不配。

D.4 匹配不下结论

_span_pair_score 的 docstring 原话：High-recall lexical/symbolic ranking, never a contradiction verdict.

分工是：匹配负责把搜索空间从"两条链的全部文本"缩到"程序能担保双方都逐字出现在原文里的那几对"；判定交给分诊模型，且模型只能在这几对里挑。
